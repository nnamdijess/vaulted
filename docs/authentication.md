# Authentication and ownership

## Architecture

FastAPI owns authentication and authorization. Passwords use argon2-cffi's Argon2id
hasher (current library defaults, random salts, and rehash-on-login). Passwords are
12–128 characters and are never trimmed, stored, or returned in plaintext. Email
validation uses email-validator through Pydantic; addresses are trimmed, normalized
and lowercased before unique storage. Names are trimmed and limited to 200 characters.

`users` stores id, email, password_hash, display_name and created_at. `sessions`
stores id, user_id, unique SHA-256 token_hash, created_at and expires_at. Tokens are
256 random bits generated by `secrets.token_urlsafe(32)`; only their hashes are in
SQLite. Registration and login issue fresh sessions and invalidate the presented
previous session. Logout deletes the current server session and clears its cookie.
Sessions expire after seven days by default; login/registration clean up expired rows.
Other devices' sessions remain valid until logout or expiration.

The cookie is `unreleased_session`: HttpOnly, SameSite=Lax, Path=/, host-only, with
Max-Age equal to the configured lifetime. It is not stored in localStorage, URLs,
API response bodies, or application logs. Auth validation errors omit submitted
input so passwords do not get echoed in error responses.

## Routes and authorization

- POST `/api/auth/register`: email, password, display_name; returns basic user data.
- POST `/api/auth/login`: email, password; returns basic user data.
- POST `/api/auth/logout`: invalidates current session; returns 204.
- GET `/api/auth/me`: id, email, display_name; returns 401 without a valid session.

All private music and project-feature handlers use an authenticated database
dependency. Every record lookup checks Project.owner_id, including through
Song.project and SongVersion.song.project. Project lists are filtered by the user,
and creation assigns owner_id from the authenticated session. Client-supplied
owner_id is rejected. Unauthorized sessions get 401; resources belonging to someone
else (or unclaimed legacy resources) get 404. This covers original audio/downloads,
artwork, versions, notes, analytics, sorting, share settings and deletion.
Uploads are never mounted as a public static directory. SQLite and upload files
must stay outside any web server's public directory.

`/api/public/{token}` and its cover/audio/listen subroutes remain separate. They
require an active random share token and verify track membership, not an owner
cookie. Public DTOs use explicit field allowlists and exclude private notes, file
paths, ownership, passwords and sessions. Existing revocation and download policy
still apply. Health and API documentation remain public, but docs contain no user data.

Next.js proxies `/api/*` to the server-only `API_INTERNAL_URL`. Browser requests,
images and audio use the same frontend origin, so authentication also covers media
and byte-range playback without exposing tokens to JavaScript. `NEXT_PUBLIC_API_URL`
is no longer used for browser music requests. Auth state starts with a deterministic
loading render; private workspaces mount only after `/auth/me` succeeds. Logged-out
private routes redirect to login. Backend authorization remains the security boundary.
Login/logout fully navigate to discard any previous private player/account state.
Public share pages remain accessible to anonymous listeners.

## Local development and existing data

Restart both servers after updating dependencies. Continue using the README's
Windows setup/run commands. Use one frontend hostname consistently (localhost and
127.0.0.1 have separate cookie jars). Register at `/register` before using the library.

Startup adds nullable, indexed `projects.owner_id` referencing users and creates
the users/sessions tables. Existing projects, IDs, songs, versions, media paths,
notes, artwork, share tokens and listens are retained. Startup never resets SQLite.
Old projects initially remain unclaimed and are hidden from every private account;
their existing public shares keep working. **The first registered user does not
receive old projects automatically.**

After registering your intended account, explicitly assign unowned projects from a
local PowerShell terminal:

```powershell
cd backend
.venv/Scripts/python.exe -m app.claim_legacy --email "your-registered-email@example.com"
```

This command assigns all currently unowned projects, reports the count, and never
transfers already owned projects. Running it again is harmless. It has no HTTP
endpoint. Back up SQLite and uploads together before any migration. No existing
library was assigned to an account as part of this implementation.

## Configuration and HTTPS

Backend `.env` (do not commit the real file):

```dotenv
COOKIE_SECURE=false
SESSION_DAYS=7
REGISTRATION_ENABLED=true
CORS_ORIGINS=["http://localhost:3000","http://127.0.0.1:3000"]
```

Frontend `.env.local`:

```dotenv
API_INTERNAL_URL=http://127.0.0.1:8000
```

For future hosting, require HTTPS, set `COOKIE_SECURE=true`, and set CORS_ORIGINS
to the exact HTTPS frontend origin(s). Keep FastAPI on loopback behind the frontend
or a trusted reverse proxy. Never use wildcard CORS with cookies. The backend rejects
browser mutations from origins outside this list or with cross-site Fetch Metadata,
including login/logout CSRF. Origin-less non-browser clients remain supported.
Set REGISTRATION_ENABLED=false after creating desired accounts if registration
should be closed. No deployment or reverse-proxy configuration is included here.

Login/registration have a bounded in-memory limit of 60 attempts per five minutes
per connecting IP. Addresses are not persisted or logged by this limiter. Behind
Next's proxy this can group users together; multiworker/Internet deployments need
a shared edge rate limiter and request-size limits. Do not blindly trust forwarded
IP headers. Infrastructure logs should omit request bodies, cookies and share URLs;
Uvicorn `--no-access-log` avoids logging public capability URLs.

## Verification

```powershell
# backend/
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m unittest discover -s tests -v
# frontend/
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run test:e2e
$env:NEXT_DIST_DIR='.next-verify'
npm.cmd run build
Remove-Item Env:NEXT_DIST_DIR
```

Backend tests use temporary databases/files. Playwright uses `.e2e-data`, ports
3011/8011, `.next-e2e`, and isolated accounts; normal library files are untouched.
Coverage includes email/password validation, hashing, cookie flags, token rotation,
expiry/logout, CSRF, private IDOR checks for reads and writes, explicit legacy claims,
anonymous share playback/revocation, browser registration/login/errors/account
isolation, and existing artwork/notes/playback/insights/theme/hydration regressions.

Manually: register Account A, create an album and upload a track; enable sharing.
Log out and confirm the private album redirects to login while its share link plays
in an incognito window. Register Account B and verify A's album is absent and its
private URL/API/audio are inaccessible. Log in as A again and disable sharing;
the old shared URL should return unavailable. Claim legacy projects only with the
local command above. Test both themes and reload; selection should persist.

## Deliberate limitations

No password recovery, verification emails, OAuth, teams, roles, admin UI, 2FA or
account/session-management UI. Email identity is unverified. Duplicate registration
returns a clear conflict. Open registration creates isolated accounts until disabled.
The rate limiter is per process and resets on restart. SQLite/media backups contain
private data and require filesystem protection. Revocation cannot recall already
buffered/downloaded audio. Analytics remain lightweight client-reported listening,
not fraud-resistant billing data.

## Upload proxy limits

Next.js buffers rewritten requests. Its default 10 MiB buffer truncates larger
multipart uploads, which can stall and return HTTP 500. The configured buffer is
512 MiB with a 120-second proxy timeout. The upload UI checks a 500 MiB total-file
limit before sending, leaving space for multipart overhead. Split larger selections
into batches. FastAPI still enforces its separate per-file limit (250 MiB by default).
Restart Next.js after changing proxy configuration. This is a bounded buffered proxy,
not a streaming upload gateway; future hosting must account for concurrent memory use.
