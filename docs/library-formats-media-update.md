# Library, output formats, and media folders

Implemented locally; not committed, pushed, or deployed to the Mac mini.

## Changes

- Studio creation and editing support 9:16 (1080×1920) and 4:3 (1440×1080). Preview, framing, lyric rasterization, and immutable render snapshots use the selected format. Format changes preserve timeline and lyric edits. Save changes before exporting.
- Music Library home and project pages now use artwork-led cards, mobile navigation, artwork playback controls, track counts/duration, and a clean numbered list. Existing project menus, sharing, notes, artwork, track actions, and player remain available. Custom themes are preserved.
- Review Media supports owner-scoped folders, rename, empty-folder deletion, and moving uploaded videos without copying files. Selection persists across folder navigation. Names are Unicode-normalized, trimmed, and case-insensitively unique per user.
- Deleting uploaded media replaces every live timeline occurrence with a protected black placeholder. Clip IDs, order, duration, music, and lyrics remain intact. The existing Replace Clip action can replace it later.
- Black is generated by the renderer and preview, so no uploaded asset is required. The supplied black video was inspected, but is not a runtime dependency.
- Files required by queued/running immutable render snapshots remain available. Durable cleanup records are retried by the Studio worker after jobs finish. Completed exports are untouched. Cleanup failures retain a retry record.
- The existing missing-lyrics fix (`-reinit_filter 0`) is retained.

## Database upgrade

Startup creates `media_folders` and `media_cleanup` through existing SQLAlchemy table creation, then runs additive, idempotent SQLite upgrades:
- `content_projects.output_format` defaults to `9:16` for legacy rows.
- `content_media.folder_id` is nullable with a foreign key and index; existing uploads remain Unfiled.
- Folder names have an owner/name-key uniqueness constraint.

Folder moves/deletions and media replacement use SQLite write transactions. Media replacement commits before physical cleanup. A failed replacement transaction leaves both references and files intact. No manual database reset is required.

## Ubuntu deployment (after review and an explicitly requested push)

Wait for active uploads and renders to finish. Back up the configured SQLite database and media directories with the existing backup process. Inspect `git status` on the Mac mini first: the earlier lyric fix was applied there directly, so preserve/reconcile that change if Git reports a conflict. Do not reset or overwrite it blindly.

Once the chosen commit is on GitHub and the server working tree is ready:

```sh
cd ~/vaulted
git pull --ff-only origin main
cd frontend
npm ci
npm run build
sudo systemctl stop vaulted-studio-worker
sudo systemctl restart vaulted-backend
sudo systemctl start vaulted-studio-worker
sudo systemctl restart vaulted-frontend
sudo systemctl --no-pager --full status vaulted-backend vaulted-studio-worker vaulted-frontend
```

The backend applies the upgrade before the worker starts. Refresh the browser/PWA afterward. No Cloudflare or Tailscale restart is needed for these features. Locally, restart the backend and Studio worker; the frontend development server reloads UI changes.
